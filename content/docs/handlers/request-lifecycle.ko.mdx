title: 요청 라이프사이클
description: 람다 event dict에서 컨트롤러 함수까지, 그리고 다시 돌아오기까지의 전체 흐름을 살펴봐요.
---

이 페이지에서는 API Gateway 요청 하나에 대한 완전한 워크스루를 다뤄요 — 동작 순서가 어떻게 되는지, 각 계층이 어떤 역할을 맡는지, 설정 노브가 어디 있는지 알려드릴게요.

## 전체 그림

```
event ─▶ @aws_handler_wrapper ─▶ handler(event, context) ─▶ router(cmd, body, headers, prefixes) ─▶ @controller fn ─▶ 리턴값
                                          │                                    │
                                          ▼                                    ▼
                                 표준 body 주입                       시그니처 기반 주입
                                 (user, source_ip, req_ts)            (body 키 → kwargs)
```

## Layer 1 — `@aws_handler_wrapper`

`sawsi.shared.handler_util`에 정의돼 있어요. `handler(event, context)`를 감싸서 그 리턴값(또는 raise된 예외)을 적절한 API Gateway 응답으로 만들어 줘요.

```python
@handler_util.aws_handler_wrapper(
    error_receiver=slack_notify,
    content_type='application/json',
    use_traceback=False,
    ignore_app_errors=[errs.no_session],
)
def handler(event, context):
    ...
```

순서대로 하는 일은 이래요:

1. `start = time.time()`을 기록해요.
2. 핸들러를 호출해요. 이후 세 분기로 나뉘어요.
3. **성공 분기** — 핸들러가 값을 리턴해요:
   - `None`이면 `{}`로 취급해요.
   - `rslt_cd = 'A00000'`, `rslt_msg = '요청 성공'`, `duration = time.time() - start`를 주입해요.
   - `AWSResponse(body, content_type, status_code=200)`로 감싸서 body를 JSON으로 직렬화하고 CORS 헤더를 추가해요.
4. **AppError 분기** — 핸들러가 `error_util.AppError`를 raise해요:
   - `{'rslt_cd': str(ex.code), 'rslt_msg': str(ex.message), 'duration': ...}`를 구성해요.
   - `ex`가 `ignore_app_errors`에 **없으면** 알림용 traceback 문자열을 인자로 `error_receiver(message)`를 호출해요.
5. **알 수 없는 예외 분기** — 그 밖의 모든 예외예요:
   - `{'rslt_cd': 'U99999', 'rslt_msg': str(ex), 'duration': ...}`를 구성해요.
   - `use_traceback=True`이면 응답에 traceback이 포함돼요 (dev에서만 쓰고, prod에서는 절대 쓰지 마세요).
   - `error_receiver`를 호출해요.

`AWSResponse` 클래스는 다음 모양의 `dict` 서브클래스예요:

```python
{
    'statusCode': 200,
    'headers': {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*',
        'Access-Control-Allow-Methods': '*',
        'Access-Control-Allow-Headers': '*',
    },
    'body': '{"rslt_cd":"A00000",...}',
    'isBase64Encoded': False,
}
```

<Callout type="warn">
핸들러에서 이미 `statusCode`/`headers`가 있는 dict를 반환하지 마세요. 래퍼가 한 번 더 감싸 버려서 응답이 망가져요. 평범한 값을 반환하거나, 정말 raw한 제어가 필요하면 래퍼를 우회하세요.
</Callout>

## Layer 2 — 요청 정규화

핸들러는 보통 `sawsi.shared.handler_util` 헬퍼로 `event`에서 세 값을 추출해요:

```python
body    = handler_util.get_body(event, context)       # JSON body 파싱, dict 반환
headers = handler_util.get_headers(event, context)    # 소문자 처리된 헤더 dict
source_ip = handler_util.get_source_ip(event, context)
```

그리고 컨트롤러가 필요할 수 있는 값으로 body를 **풍부하게** 만들어 줘요:

```python
body['user'] = None              # session_id가 풀리면 나중에 설정해요
body['source_ip'] = source_ip
body['req_ts'] = int(event['requestContext']['requestTimeEpoch']) / 1000
```

이 세 키는 컨벤션이에요. `user`/`source_ip`/`req_ts`를 이름으로 받는 컨트롤러 시그니처는 Layer 4의 시그니처 주입 덕분에 자동으로 값을 받아요.

## Layer 3 — `router()`

시그니처는 이래요:

```python
router(cmd: str, body: dict, headers: dict, allowed_cmd_prefixes: list) -> Any
```

책임은 두 가지예요:

### 3a. 보안 게이트

라우터는 다른 무엇보다 먼저 `cmd`가 허용된 prefix 중 하나로 시작하는지 검사해요:

```python
if not any(cmd.startswith(prefix) for prefix in allowed_cmd_prefixes):
    raise error_util.Command_Prefix_not_allowed
```

또 `cmd`의 **모듈** 부분(마지막 `.` 이전 전체)에 대해서도 2차 검사를 해요 — 조작된 `cmd` 문자열이 의도치 않은 prefix를 통해 컨트롤러에 도달하지 못하도록 막아 줘요.

<Callout type="warn">
`allowed_cmd_prefixes=[]`나 `['*']`를 절대 넘기지 마세요. 이 리스트가 라우팅 보안의 전 둘레예요. 사용자용 람다는 `<app>.controller` prefix만 허용해야 하고, 어드민 람다는 `admin.controller`만 허용해야 해요.
</Callout>

### 3b. Python import 경로로 디스패치

라우터는 `@controller`가 채워 둔 `controller_registry`에서 `cmd`를 조회해요. 찾으면 **시그니처 기반 인자 주입**(Layer 4)으로 함수를 호출해요.

해당 모듈이 아직 import되지 않았다면 — 예를 들어 이 람다 컨테이너에서 처음 호출되는 컨트롤러라면 — 라우터가 lazily import하고, 그 과정에서 `@controller` 데코레이터가 실행되면서 함수가 등록돼요.

## Layer 4 — `@controller`와 시그니처 주입

데코레이터 자체는 작아요:

```python title="sawsi/handler/controller_decorator.py"
controller_registry = {}

def controller(func):
    controller_registry[f'{func.__module__}.{func.__name__}'] = func
    return func
```

흥미로운 부분은 `router()` 안에 있어요:

```python
signature = inspect.signature(func)
filtered_body = {k: v for k, v in body.items() if k in signature.parameters}
return func(**filtered_body)
```

라우터가 함수의 파라미터 이름을 가져와서 `body`에서 그 키들만 뽑아 가요. 무관한 키는 조용히 버려져요.

### 컨트롤러 작성자에게 의미하는 것

```python
@controller
def update_profile(user, name: str, birth: str | None = None, **kwargs):
    if user is None:
        raise errs.no_session
    user.name = name
    if birth:
        user.birth = birth
    user.update()
    return {'name': user.name}
```

- `user`는 `body['user']`에서 와요 (Layer 2의 핸들러가 설정해 둔 값이에요).
- `name`/`birth`는 요청 필드에서 와요.
- `**kwargs`가 핸들러가 추가로 주입한 키들(`source_ip`, `req_ts` 등)을 받아 줘요. **항상 `**kwargs`를 포함해 주세요** — 미래에 핸들러가 키를 추가해도 호출자가 깨지지 않게 해 줘요.

### 보안적 의미

라우터가 `body` 자체를 넘기지 않고 함수가 요청한 필드만 넘기기 때문에, 컨트롤러가 보지 말아야 할 필드를 실수로 읽을 수 없어요. 파라미터 오염 버그에 대한 작지만 실재하는 방어예요.

## Layer 5 — 리턴값

JSON으로 직렬화할 수 있는 어떤 값이든 괜찮아요. 래퍼가 응답 봉투에 당신의 dict를 합쳐 줘요:

```python
return {'message': 'ok', 'data': {...}}
# 다음이 돼요
# {'rslt_cd': 'A00000', 'rslt_msg': '요청 성공', 'duration': 0.012,
#  'message': 'ok', 'data': {...}}
```

실패를 신호하려면 `AppError`를 raise하세요:

```python
from sawsi.shared.error_util import AppError
raise AppError('B10042', 'invalid_phone_number')
```

전체 코드 체계(`A` 성공, `B` 비즈니스 에러, `U` 알 수 없음)는 [에러 & 결과 코드](/docs/architecture/errors)에서 다뤄요.

## 콜드스타트 신호

옵저버빌리티를 위해 콜드스타트를 감지하는 흔한 패턴을 소개할게요:

```python title="main/aws_handler.py"
import time
COLD_START_AT = time.time()
COLD = True

@handler_util.aws_handler_wrapper(...)
def handler(event, context):
    global COLD
    cold_start = COLD
    COLD = False
    body = handler_util.get_body(event, context)
    body['cold_start'] = cold_start
    ...
```

비용도 없고 구조화 로그에 잘 표시돼요.

## 여기에 **없는** 것

- 미들웨어 시스템은 없어요. pre/post 훅이 필요하면 핸들러 본문에서 `router(...)` 앞/뒤에 두세요. 프레임워크는 의도적으로 경로를 직선으로 유지해요.
- DI 컨테이너도 없어요. 상태 공유는 `api.py`를 import해서 해요.
- `before_request`/`after_request` 데코레이터도 없어요. 래퍼가 컨트롤러보다 한 단계 위에 있고, 컨트롤러별 훅은 없어요.
