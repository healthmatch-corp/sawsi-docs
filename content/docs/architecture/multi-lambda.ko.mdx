title: 다중 람다 구성
description: 한 프로젝트, 여러 람다 — 디렉터리, 공유 싱글턴, cmd prefix가 공존하는 법을 알려드려요.
---

실제 sawsi 프로젝트는 보통 람다 하나 이상으로 자라요. 이 페이지에서는 표준 토폴로지, 각 람다가 따르는 디렉터리 레이아웃, 그리고 "여러 람다, 하나의 코드베이스"가 실제로 동작하도록 공유 코드가 구성되는 방법을 다뤄요.

## 표준 토폴로지

프로덕션 프로젝트는 보통 람다 6~8개를 가져요.

```
                         ┌───────────────────────┐
   클라이언트 앱 ─────────▶│ main (API Gateway)    │
                         └───────────┬───────────┘
                                     │ enqueue
                                     ▼
                         ┌───────────────────────┐
                         │ queue_receiver (SQS)  │
                         └───────────────────────┘

   어드민 클라이언트 ──▶│ admin (API Gateway)   │
                         └───────────────────────┘

   서드파티 ────────────▶│ webhook_receiver      │
                         └───────────────────────┘

   EventBridge ─────────▶│ scheduler (1분)       │─▶ 푸시, 정리, 배치
                         └───────────────────────┘

   S3 업로드 ────────────▶│ s3trigger              │─▶ 이미지/비디오 변환
                         └───────────────────────┘

   ws 클라이언트 ──────▶│ websocket_receiver    │
                         └───────────────────────┘

   공개 사이트 ──────────▶│ land (API Gateway)    │─▶ 비인증 읽기
                         └───────────────────────┘
```

사용자 대면 람다와 워커 람다를 왜 분리할까요? 두 가지 이유가 있어요.

1. **IAM 폭발 반경.** 워커가 더 넓은 DynamoDB 쓰기 권한이나 더 긴 실행 타임아웃을 필요로 할 수 있어요. 분리하면 사용자 대면 함수를 최소 권한으로 유지할 수 있어요.
2. **콜드스타트와 메모리 프로필.** 비디오 처리 워커는 ffmpeg과 1–2GB 메모리가 필요해요. 사용자 API는 둘 다 불필요하고 작은 이미지와 빠른 시작에서 이득을 봐요.

## 디렉터리 레이아웃

모든 람다 앱이 최상위 디렉터리 하나씩 가져요.

```
myproject/
├── api.py                   # 공유 싱글턴 AWS 클라이언트
├── config.py
├── errs.py
├── build_keeper.py
├── Dockerfile.main          # 람다 flavor별 Dockerfile 하나씩 (옵션)
├── Dockerfile.sqs
├── buildspec-dev.yml
├── buildspec-prod.yml
├── aws_iam_policy_dev.json
├── aws_iam_policy_prod.json
├── main/
│   ├── aws_handler.py       # 람다 진입점
│   ├── controller/          # @controller 함수들
│   ├── service/             # 비즈니스 로직
│   ├── dao/                 # 데이터 접근 헬퍼 (무거운 쿼리, 집계)
│   ├── model/               # DynamoModel 정의
│   ├── dto/                 # 필요 시 Pydantic 입출력 스키마
│   ├── constant/            # enum, literal 모음
│   ├── migration/           # 일회성 데이터 마이그레이션
│   └── doc_maker.py
├── admin/
│   ├── aws_handler.py
│   ├── controller/
│   ├── service/
│   ├── model/
│   └── doc_maker.py
├── queue_receiver/
├── scheduler/
├── webhook_receiver/
├── websocket_receiver/
├── s3trigger/
├── land/
├── common/                  # 어느 한 람다에 속하지 않는 앱 간 코드
├── shared/                  # 유틸 래퍼 (slack, push, sms 래퍼 등)
└── converter/               # 비-람다 코드 (CLI 도구 등)
```

각 람다 디렉터리가 같은 네 개 하위 폴더(`controller`, `service`, `model`, 선택적으로 `dao`)를 공유해요. 역할은 이래요.

| 폴더 | 책임 |
|---|---|
| `controller/` | `@controller` 데코레이터 함수. 요청 필드를 받고, `AppError`를 raise하고, 결과 dict를 반환해요. 가능하면 I/O 없이 — `service/`에 위임해요. |
| `service/` | 비즈니스 로직. 모델과 외부 서비스를 오케스트레이션해요. 클래스가 아니라 함수예요. |
| `dao/` | 무거운 쿼리, 배치 작업, 집계. 데이터 모양이 한 모델에 깔끔히 들어가지 않는 모든 것을 담아요. |
| `model/` | `DynamoModel` 서브클래스 + 그들의 클래스메서드. 스키마가 여기 있어요. |

## 람다 간 코드 공유

`api.py`, `config.py`, `errs.py`, `build_keeper.py`, 그리고 `shared/` + `common/` 디렉터리는 모든 람다가 import해요. **모든 람다가 같은 Docker 이미지 소스를 공유**하기 때문에 작동해요 — `awsi`가 코드베이스를 쪼개지 않고 여러 `aws_handler.py` 진입점만 생성해요.

`main` 람다가 `admin/`의 무언가에 의존하면 어떻게 될까요? 그러면 안 돼요. 공유돼야 할 코드는 `shared/`나 `common/`에 속해요. 람다별 디렉터리는 자체 완결로 유지해 주세요.

하지만 `main/model/event.py`에 정의된 모델은 `queue_receiver/`에서 읽힐 수 있어요 — 같은 코드 베이스, 같은 Python 모듈이니까요. 워커가 종종 main의 데이터 **위에서** 작동하고 자신만의 중복 모델이 필요 없기 때문이에요.

## 람다별 `aws_handler.py` 차이

모든 핸들러가 `event`에서 추출하지만, 추출은 트리거별로 달라요.

```python
# main/aws_handler.py — API Gateway
body = handler_util.get_body(event, context)
headers = handler_util.get_headers(event, context)

# queue_receiver/aws_handler.py — SQS
for record in event['Records']:
    msg = json.loads(record['body'])
    cmd, body = msg['type'], msg['body']

# scheduler/aws_handler.py — EventBridge
# event는 사실상 비어 있음; ScheduledTask 사용

# websocket_receiver/aws_handler.py — WebSocket
route_key = event['requestContext']['routeKey']
connection_id = event['requestContext']['connectionId']

# s3trigger/aws_handler.py — S3 event
for record in event['Records']:
    key = record['s3']['object']['key']

# webhook_receiver/aws_handler.py — HTTPS POST
cmd = event['queryStringParameters']['cmd']
body = handler_util.get_body(event, context)
```

트리거별 전체 워크스루는 [트리거](/docs/handlers/triggers)에서 확인하세요.

## `common/`, `shared/`, `converter/`

| 폴더 | 담는 것 |
|---|---|
| `common/` | 앱 간 공유되는 프로젝트 고유 로직 (예: 공유 이미지 생성, 통계 계산). `api.py`에서 import해요. |
| `shared/` | `sawsi.aws.*`가 커버하지 않는 서드파티 서비스 래퍼 — Firebase 푸시, Slack webhook, ppurio SMS, KakaoTalk API 등. 각각 단순 함수를 노출하는 작은 모듈이에요. |
| `converter/` | 비-람다 코드: CLI 도구, 일회성 스크립트, 내부 유틸리티예요. |

최상위(앱 하나 안이 아니라)에 두면 의존 방향이 명시적이 돼요 — 앱이 `common/`/`shared/`에 의존하지, 반대가 아니에요.

## 분리하지 *말아야* 할 때

람다 추가에는 비용이 있어요 — `aws_handler.py` 하나, buildspec 항목 하나, IAM ARN 하나, `LAMBDAS` JSON 배열 항목 하나. 이유가 있을 때까지는 분리하지 마세요. 분리를 정당화하는 이유들은 이래요.

- 두 번째 트리거 소스 (SQS 필요가 생긴 경우).
- 10배 다른 메모리/타임아웃 프로필 (비디오 처리).
- 의미 있게 다른 IAM 경계 (어드민 vs 사용자).
- 프로젝트의 나머지와 모델을 공유하지 않을 명확한 경계 컨텍스트.

새 코드가 같은 트리거·프로필의 "엔드포인트 더 추가"라면, 람다가 아니라 컨트롤러를 추가해 주세요.

## 빌드 산출물

컨테이너 이미지 배포 경로는 Dockerfile마다 이미지 하나를 빌드하고 buildspec post_build당 람다 함수 **N개**를 업데이트해요. buildspec의 `LAMBDAS` JSON 배열이 어느 람다 함수가 어느 이미지를 받을지 나열해요.

```json
[
  {"name": "dev_myproject_main_docker",         "handler": "main.aws_handler.handler",          "image": "main", "memory": 1800},
  {"name": "dev_myproject_admin_docker",        "handler": "admin.aws_handler.handler",         "image": "main", "memory": 1024},
  {"name": "dev_myproject_queue_receiver",      "handler": "queue_receiver.aws_handler.handler", "image": "sqs",  "memory": 2048},
  {"name": "dev_myproject_scheduler",           "handler": "scheduler.aws_handler.handler",      "image": "main", "memory": 1024},
  {"name": "dev_myproject_s3trigger",           "handler": "s3trigger.aws_handler.handler",      "image": "sqs",  "memory": 2048},
  {"name": "dev_myproject_websocket_receiver",  "handler": "websocket_receiver.aws_handler.handler", "image": "main", "memory": 512},
  {"name": "dev_myproject_webhook_receiver",    "handler": "webhook_receiver.aws_handler.handler", "image": "main", "memory": 512}
]
```

`main` 이미지는 API Gateway 스타일 함수가, `sqs` 이미지(ffmpeg, 더 큰 의존성)는 워커가 사용해요. buildspec 자세한 내용은 [배포](/docs/deployment/deployment)를 참고하세요.
