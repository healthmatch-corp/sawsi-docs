sawsi는 옵저버빌리티 벤더에 대한 의견이 없어요 — 단지 **신호가 어디서 오는지**에 대한 의견만 있어요. 모든 프로젝트가 무료로 얻는 네 가지 신호와, 그 위에 쌓을 패턴들을 알려드릴게요.

## 1. CloudWatch Logs (무료)

모든 `print()`, 모든 `logging.info()`, 그리고 람다의 stdout/stderr 전체가 `/aws/lambda/<function-name>` 아래 CloudWatch Logs에 안착해요. 설정이 필요 없어요.

요청당 래퍼 자체는 로그 한 줄도 내놓지 않아요 — 의도적이에요, 콜드 경로 오버헤드를 0에 가깝게 유지하기 위해서예요. 요청 로그가 필요하면 핸들러에서 수동으로 작성해 주세요.

```python
def handler(event, context):
    body = handler_util.get_body(event, context)
    cmd = body.get('cmd')
    print(json.dumps({
        'event': 'request',
        'cmd': cmd,
        'source_ip': handler_util.get_source_ip(event, context),
        'ts': time.time(),
    }))
    ...
```

모든 로그 줄을 JSON 포맷으로 작성해 주세요. CloudWatch Logs Insights가 이후 필터링과 집계를 할 수 있어요.

## 2. Firehose 경유 S3로 구조화 로그

장기 보존과 분석을 위해 `api.firehose_log`로 로그를 라우팅해요.

```python
api.firehose_log.put_record(json.dumps({
    'event': 'event_join',
    'user_id': user.id,
    'event_id': event.id,
    'duration_ms': int(duration * 1000),
    'ts': time.time(),
}))
```

Firehose가 버퍼링하고 ~5분마다 S3에 dump해요. 거기서 Athena나 당신의 웨어하우스가 픽업해요.

여기가 **비즈니스 이벤트**(가입, 결제, 참여, 이탈 신호)를 두는 자리예요. **디버그 출력**은 CloudWatch Logs에 두면 돼요.

## 3. 콜드스타트 추적

`aws_handler.py` 상단의 흔한 패턴이에요.

```python
import time
COLD_START_AT = time.time()
COLD = True

@aws_handler_wrapper(...)
def handler(event, context):
    global COLD
    cold_start = COLD
    COLD = False
    ...
    # 로그에 cold_start 포함
```

Python 모듈은 컨테이너당 한 번 로드돼요 — 그래서 `COLD_START_AT`은 컨테이너가 새로 초기화될 때 설정돼요. 같은 컨테이너 안의 모든 후속 호출은 warm이에요. 이 신호를 내놓으면 트래픽이 콜드 경로에 얼마나 자주 부딪히는지 볼 수 있어요.

## 4. Slack/Discord 에러 알림

`@aws_handler_wrapper`의 `error_receiver`가 알림 파이프예요. Slack이 가장 흔한 목적지예요.

```python title="shared/slack/notifier.py"
import requests

def slack_notify(message: str):
    try:
        requests.post(
            SLACK_WEBHOOK_URL,
            json={'text': f'```{message[:2000]}```'},
            timeout=2,
        )
    except Exception:
        pass   # 알림 자체가 오콜을 호출하지 않게

@aws_handler_wrapper(error_receiver=slack_notify, ignore_app_errors=[...])
def handler(event, context):
    ...
```

두 가지 규칙이 있어요.

- HTTP 호출에 **타임아웃을 설정**해요. 느린 Slack 엔드포인트가 람다 실행을 늘리면 안 돼요.
- 알림 함수에서 **예외를 삼켜요**. Slack이 다운돼도 람다는 응답해야 해요 — 알림만 없을 뿐이에요.

## 5. X-Ray (옵션)

람다 함수에 AWS X-Ray를 활성화하고 (AWS 콘솔), IAM 정책에 X-Ray 쓰기 권한을 부여해요. SDK가 boto3 호출을 자동 계측하므로 각 AWS SDK 호출이 sub-segment로 표시돼요.

코드 내부의 커스텀 세그먼트예요.

```python
from aws_xray_sdk.core import xray_recorder

@xray_recorder.capture('compute_match_score')
def compute_match_score(user_a, user_b):
    ...
```

X-Ray는 백만 트레이스당 소액 비용이지만 요청당 flame graph를 줘요.

## 래퍼가 측정하는 것

모든 응답에 `duration` 필드가 있어요 — 핸들러의 wall-clock 초예요. 상상할 수 있는 가장 저렴한 지연 신호예요. Athena에서 `cmd`로 집계해 보세요.

```sql
select cmd, count(*), avg(duration), approx_percentile(duration, 0.95)
from request_logs
where date = '2026-05-13'
group by cmd
order by avg(duration) desc;
```

## SLO / 오콜

알림 시작 세트예요.

| 알림 | 조건 |
|---|---|
| 에러율 급증 | `rslt_cd`가 `U`로 시작하는 요청이 5분 동안 1% 초과 |
| 지연 회귀 | 임의 cmd의 p95 `duration`이 기준선 대비 10분 동안 2배 |
| 워커 백로그 | SQS `ApproximateNumberOfMessagesVisible` > N이 10분 |
| 스케줄러 누락 | EventBridge 호출 카운트가 5분 동안 분당 1 미만 |
| Firehose 지연 | records-in 대비 records-delivered 간격이 정상의 10배 초과 |

CloudWatch Alarms가 임의 지표에 대해 구성 가능하며 같은 Slack webhook으로 게시할 수 있어요.

## 람다별 동시성

함수당 CloudWatch 지표 `Concurrent Executions`가 몇 개의 컨테이너가 살아 있는지 보여줘요. 계정 전체 한도(기본 1,000)와 비교해 접근 중인지 이해해 주세요.

중요 함수의 Reserved Concurrency가 함대의 나머지로부터 격리해요 — 시끄러운 워커가 굶기면 안 되는 사용자 대면 엔드포인트에 유용해요.

## 비용을 신호로

두 비용 라인이 기능적 신호보다 먼저 흘러요.

- **DynamoDB on-demand**. RCU/WCU 급증이 종종 성능 이슈에 선행해요.
- **Lambda duration**. `duration` 회귀가 더 많은 GB-초로 나타나요.

당신의 스케일에 맞는 입도로 둘 다에 CloudWatch billing alarm을 설정해 주세요.

## 대시보드

환경당 최소 CloudWatch 대시보드예요.

- 함수당 Lambda 호출 + 에러 + 지연.
- API Gateway 4xx/5xx 카운트.
- 테이블당 DynamoDB 소비 용량.
- 큐당 SQS visible/in-flight 카운트.

로그 볼륨이 신경 쓰이면 Firehose / S3 바이트 카운트를 추가해 주세요.

## 이것이 *아닌* 것

- 트레이싱 프레임워크가 아니에요. X-Ray는 통합되지만 옵션이에요 — sawsi가 자체 출시하지 않아요.
- 지표 라이브러리가 아니에요. `metric.inc('login.success')` 같은 단축이 없어요. 구조화 로그를 Firehose에 내놓고 웨어하우스에서 집계해 주세요.

원한다면 위에 쌓아 보세요. sawsi 컨벤션은 프레임워크는 작게, 신호는 데이터 플레인(로그, S3, DynamoDB)에 두고, 다운스트림에서 집계예요.
