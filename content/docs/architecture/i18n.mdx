For multilingual apps, sawsi projects often need to serve UI strings, push notifications, and validation messages in multiple languages. The framework doesn't ship an i18n module — but the production pattern most projects converge on is small enough to document here.

## The three-tier cache

The pattern is a **read-through cache** with three layers:

```
tr(text, fyi, group, lang) 
   │
   ▼
1. Local JSON (locale.json bundled in the Lambda image)
   │ miss
   ▼
2. DynamoDB Translation table
   │ miss
   ▼
3. LLM call (Bedrock/OpenAI) → store in DynamoDB → return
```

- **Build-time JSON** — generated by `build_keeper.py`, baked into the Lambda image. Zero-cost lookups for already-translated strings.
- **DynamoDB** — translations added at runtime (after image was built). Survives container recycles.
- **LLM fallback** — first time a new string is requested, ask the model to translate, store the result. Subsequent reads hit the DynamoDB layer.

## The Translation model

```python title="model/translation.py"
import hashlib
from sawsi.model.base import DynamoModel, sync
import api

@sync
class Translation(DynamoModel):
    __dynamo__ = api.dynamo
    _table = 'translation'

    text: str             # original (typically Korean)
    fyi: str = ''         # context hint for the translator/LLM
    group: str = 'common'
    call_trace: str = ''  # file:line:context — for finding stale entries

    # One column per supported language
    ko: str = ''
    en: str = ''
    es: str = ''
    zh_Hans: str = ''
    ja: str = ''
    pt: str = ''

    @staticmethod
    def make_key(group, text):
        return hashlib.sha256(f'{group}:{text}'.encode()).hexdigest()
```

The primary key is a SHA-256 of `group + text`, so changes to either produce a new row (avoiding cache collisions).

## The `tr()` function

```python title="translation.py"
import inspect, json, os
from main.model.translation import Translation
import api

# Bundled into the image at build time
TR_DATA = {}
locale_path = f'{config.env}-locale.json'
if os.path.exists(locale_path):
    with open(locale_path) as f:
        for row in json.load(f):
            TR_DATA[row['id']] = row

def tr(text: str, fyi: str = '', group: str = 'common') -> Translation:
    key = Translation.make_key(group, text)

    # 1. local cache
    if key in TR_DATA:
        return Translation(**TR_DATA[key])

    # 2. DynamoDB
    record = Translation.get(key)
    if record:
        TR_DATA[key] = record.model_dump()
        return record

    # 3. LLM fallback
    record = _translate_with_llm(text, fyi, group)
    record.id = key
    record.call_trace = _capture_trace()
    record.put(can_overwrite=True)
    TR_DATA[key] = record.model_dump()
    return record
```

Callers then pick the right language:

```python
phrase = tr('환영합니다', group='onboarding').en
```

## Build-time dump

The `build_keeper.py` step that dumps the locale file:

```python title="translation.py (continued)"
def make_locale_json():
    rows = []
    for t in Translation.generate():
        rows.append(t.model_dump())
    with open(f'{config.env}-locale.json', 'w') as f:
        json.dump(rows, f, ensure_ascii=False)
```

This runs during `docker build`, so the deployed Lambda starts with a hot local cache.

## Supported languages

Add a column to `Translation` per language. A typical lineup:

| Code | Language |
|---|---|
| `ko` | Korean |
| `en` | English |
| `es` | Spanish |
| `zh_Hans` | Simplified Chinese |
| `ja` | Japanese |
| `pt` | Portuguese |

The cost of adding a language is one column + one LLM call per existing string (amortized as users encounter strings in that language).

## Capturing the call site

`inspect.stack()` lets you record where a `tr()` call originated:

```python
def _capture_trace():
    frame = inspect.stack()[2]
    return f'{frame.filename}:{frame.lineno}'
```

Stored in the `call_trace` field, this is invaluable when you later want to **prune** translations whose source code has been deleted.

## The `fyi` hint

For ambiguous source strings, pass a `fyi`:

```python
tr('주문', fyi='An e-commerce order, not a sorting order', group='shop').en
```

The LLM uses `fyi` as system context. Without it, "주문" might translate as "order" but mean either "an order placed" or "sequence".

## What this is *not*

- Not a UI string extraction tool. You write `tr(...)` calls inline; there's no `extract` step.
- Not a translation memory editor. Edit the DynamoDB row directly (via admin) when a generated translation is wrong.
- Not full ICU plural/gender handling. For "1 item" vs "5 items" you write the conditional in Python.
